# 架构落地路线图（本地优先 -> 云扩展）

## Phase 1：本地 MVP（2~4 周）

目标：单机可用闭环。

- 交付范围：
  - 任务引擎：每日下发、完成打卡、补救任务插入
  - 奖励经济：Coin 结算、道具与现实奖励兑换、预算护栏
  - 后果系统：日级/周级惩罚与恢复
  - 职业系统：周职业选择与任务映射
  - AI 对话：NPC 聊天与基础降级
- 数据层：
  - SQLite + 逻辑表落地（参考 `docs/database/logical_schema.sql`）
- 验收口径：
  - 离线可完成任务/奖励/后果流程
  - 在线可完成 3 轮以上 NPC 对话

## Phase 2：可扩展准备（2~3 周）

目标：稳定演进，不改业务语义。

- 交付范围：
  - 代码模块化（应用层 / 领域层 / 基础设施层）
  - Prompt Registry DB 覆写能力
  - 审计日志与可观测指标
  - Sync 抽象与导出导入协议
- 数据层：
  - 增量迁移脚本与初始化种子数据
- 验收口径：
  - 更换 AI Provider Adapter 不影响前端 API
  - 核心交易（任务完成与兑换）保持事务一致性

## Phase 3：云扩展（3~6 周）

目标：多设备同步与可运维。

- 交付范围：
  - 用户账户与鉴权
  - PostgreSQL 生产数据库
  - 同步队列与冲突解决策略
  - 多 Provider AI 路由与成本控制
- 验收口径：
  - SQLite -> PostgreSQL 迁移后业务接口不变
  - 离线操作可重放，冲突可解释
  - AI 调用失败可自动降级且不阻塞主流程
